# HR audit — checklist перед переносом в main

Это эскиз функциональности. Проверки на живом сайте выполняются после отдельного согласования переноса в `main`.

## Сценарии

- [ ] Только отправка формы `type === 'report'` создаёт запись кадрового аудита.
- [ ] Форма запроса на повышение и другие формы не создают запись аудита.
- [ ] Номер выделяется атомарно в Redis и не меняется после создания.
- [ ] Повторный HTTP-запрос с тем же ID отправки возвращает существующую запись, а не создаёт вторую.
- [ ] Данные заявки и история сохраняются до отправки в Discord.
- [ ] Ошибка Discord оставляет запись в статусе ожидания доставки.
- [ ] Проверяющий может повторить доставку без повторного создания записи.
- [ ] Проверяющий может открыть полный список заявок и историю действий.
- [ ] Одобрение/отклонение доступно только Discord ID `200102286473691139`.
- [ ] Решение можно принять только один раз; параллельные запросы не перезаписывают друг друга.
- [ ] Для отказа обязательна причина длиной 1–1000 символов.
- [ ] Сохраняются reviewer ID, имя, время и решение.
- [ ] Уведомление о решении использует webhook соответствующего отдела.
- [ ] При сбое уведомления решение остаётся сохранённым, уведомление можно повторить.
- [ ] Упоминания автора и проверяющего находятся вне Discord Embed.
- [ ] Будущий документ отправляется только через отдельный `WEBHOOK_HR_AUDIT` в канал `1514608895597740128`; webhook отдела для этого не используется.
- [ ] Если `WEBHOOK_HR_AUDIT` не настроен, это не блокирует кадровое решение.

## Перед переносом

- [ ] Сверить все пункты с исходным ТЗ.
- [ ] Согласовать поведение повторной отправки при неопределённом результате запроса Discord, чтобы не создавать дубли.
- [ ] Подготовить и проверить шаблон будущего документа.
- [ ] Только после согласования перенести изменения в `main`.
- [ ] На живом проекте проверить сценарии с тестовыми заявками и реальными OAuth/Redis/Discord-настройками.

## Граница текущей работы

Не выполнялись production smoke tests, не менялись настройки production и не выполнялся перенос в `main`.
